# Agent Operating Rules

Read this before writing any code in this repository.

## Stage-gated, minimal

Work is locked into explicit stages (see `README.md` and `AI_DEV_PACK.md` §9).
Build **only** the stage you've been asked to build. Do not start the next
stage's work "while you're in there," even if it looks convenient. Each stage
ends with an explicit review before the next one starts.

## No silent business-rule invention

Every business rule in this system was deliberately decided, not assumed —
see `docs/decisions/` for the log. If you hit a case the decisions log and
`AI_DEV_PACK.md` don't cover:

- **Stop and ask**, in your response to the person running this session.
- Do not guess a "reasonable default" and proceed silently.
- Do not infer a rule from what similar apps usually do.

Examples of things that must never be invented silently: due dates, grace
periods, scoring thresholds, retention windows, what counts as a valid
category/frequency for an indicator, or what a print pack should include.
All of these are already decided in `AI_DEV_PACK.md` — use those values.

## No automatic publishing

This applies especially to Section B (AI Drafting Assistant). A generated
document or template is a `Draft` with `status=draft` until a human explicitly
approves it. Nothing generated by AI becomes filed evidence, gets written to
`is_current=true`, or appears in a print pack without that approval step.
Do not build a path that skips this, even for testing convenience — write a
separate seed/fixture script instead if you need sample "approved" data.

## Data integrity

`docs/data/indicators_master.json` is the canonical, locked indicator registry
(118 records). Do not hand-edit it. Do not regenerate it from the source MSDS
manual — that extraction and classification work is already done and reviewed.
If the loader needs to transform it, do so in code, leaving the source file
untouched.

## Definition of done, per stage

Each stage prompt in `AI_DEV_PACK.md` §9 includes its own "definition of done."
Don't mark a stage complete until every item in that list is verifiably true —
spot-check against the source data, don't just confirm the code runs.

## When in doubt

Prefer stopping and asking over shipping a guess. A stalled stage costs a
question; a wrong assumption baked into the compliance model costs trust in
the whole system's numbers.
